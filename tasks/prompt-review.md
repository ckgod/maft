# MAFT 프롬프트 검토 (2026-05-21)

## 검토 방법

- `server/src/prompt.ts` 의 `FEYNMAN_TEMPLATE` 전문
- `server/src/topics.ts` — 토픽 콘텐츠가 프롬프트에 들어가는 방식 (`loadTopicContent` = .md 원문 그대로)
- 샘플 토픽 `Q12-State-hoisting.md` 원문 구조
- 실측 데이터 — 이 검토 직전 같은 토픽으로 직접 4턴 학습 세션을 돌린 채점 결과 (부록 참조)

## 한 줄 결론

**학습 대화 자체는 동작한다. 그러나 점수·진척 추적 레이어가 구조적으로 깨져 있어,
점수를 신뢰할 수 없고 마스터 도달이 사실상 운에 좌우된다.**

파인만 코칭 루프(설명 → 평가 → 역질문)는 정상 작동한다. 문제는 그 위에 얹은
"채점 + 누적 약점 + 마스터" 측정 레이어다. 측정이 깨지면 학습 도구로서의
핵심 가치(README: "어떤 토픽을 얼마나 깊이 이해했는지가 그대로 드러난다")가 무너진다.

## 잘 되어 있는 것 (유지할 것)

- **청자 재정의** — "12살" 대신 "이 토픽 처음 듣는 동료 개발자". 안드로이드 학습에 적확하다.
- **jargon 회피 차단** — 용어를 풀이 없이 쓰면 한 줄 정의 요구. 이해 부족을 가리는 걸 막는 좋은 장치.
- **점수 인플레이션 방지** 의도 자체는 옳다 (다만 부작용 있음 — P7).
- **토픽 범위 가드레일** — 인접 토픽으로 새지 않게 하는 의도는 타당.
- 출력 형식 강제(JSON 블록)는 이제 안정적 (resume 수정 후).

## 문제 (심각도 순)

### P1 — 개념 분해가 자의적이고 불안정하다 (★★★ 최상위 근본 원인)

프롬프트는 "코치인 당신이 토픽 원문에서 자연스러운 순서로 핵심 개념을 **내부적으로** 잡아"
라고만 지시한다. 핵심 개념 목록이:

- 어디에도 고정·기록되지 않는다. LLM이 매 턴 머릿속에서 새로 만든다.
- 결국 LLM은 **문서의 불릿 헤더를 그대로** 개념으로 쓴다. 실측: missed_concepts 6개 중
  5개가 `Q12.md` 의 "### State hoisting의 주요 이점" 불릿 5개와 **글자 그대로 일치**.
- 이 불릿들은 학습 단위가 아니다. "향상된 재사용성 / 간소화된 테스트 / 향상된 관심사 분리"는
  전부 *하나의 원인*(stateless → 관심사 분리)의 *결과*다. 이걸 각각 별도 개념으로 떼어
  따로따로 score≥3 을 받게 하는 건 인위적이고 지루하다.
- 내부·매턴 재생성이므로 **비결정적**이다. 같은 토픽도 세션마다 개념 집합이 달라질 수 있다.

→ 아래 P2~P4 가 전부 여기서 파생된다.

### P2 — "한 턴 = 한 개념" 평가와 missed_concepts 추적이 서로 어긋난다 (★★★)

프롬프트에 양립 불가한 두 모델이 동시에 돈다:

- **모델 A**: "이번 턴 = 한 개념, 그 한 개념만 평가" → 턴당 점수 1개
- **모델 B**: missed_concepts = 세션 전체에서 아직 안 짚은 개념 집합, 마스터 = 모든 개념 각각 score≥3

학습자 답변 하나가 여러 추적 개념을 동시에 건드리면 어떻게 되는지 프롬프트가 정의하지 않는다.
실측 T2: 학습자가 "SSOT·일관성·테스트·재사용·단방향 흐름"을 한 답변에 담았다 — 추적 개념 6개 중
4개를 실제로 다뤘다. 그런데 **점수 2, missed_concepts 에서 제거된 개념 0개.**

가장 치명적인 점: **마스터 조건은 "개념별 score≥3"을 요구하는데, 시스템은 개념별 점수를
계산하지 않는다.** `turns` 테이블에도 `score` 컬럼은 턴당 1개뿐이다. 개념별 점수가
어디에도 존재하지 않으므로, "개념별 ≥3" 추적은 LLM의 기억에 의존한 허구다.

→ 학습자가 좋은 답을 해도 약점 패널이 안 줄어든다. 핵심 피드백 루프가 끊긴다.

### P3 — 점수가 일관되지 않다 (★★★)

실측 4턴 점수: **3 → 2 → 1 → 4.** 모두 합리적인 답변이었다.
특히 T3(애니메이션·스크롤 위치 등 transient 상태는 내부 보유 — 문서 deflist와 일치하는 정답)이 **1점**.

원인:
- 0~5 루브릭이 "한 개념" 기준인데 "한 개념"이 매 턴 흔들린다 (P1). 채점 기준점이 고정 안 됨.
- 루브릭 밴드가 "대부분 짚음 / 한두 가지 빠짐" 같은 정성 표현뿐. **이 토픽에서 3점이
  구체적으로 뭔지** 앵커가 없다. LLM이 매번 잣대를 새로 발명한다.
- 채점 예시(exemplar)가 없다.
- "한 턴 = 한 개념 + 다음 개념으로 이동" 구조라 매 턴이 새 개념의 *콜드 첫 시도*다.
  콜드 첫 시도는 자연히 낮게 나온다 → 점수가 1~3에 눌리고 노이즈가 크다.
- 흐름 규칙 위반도 관찰: T2 점수 2 → 규칙상 "보강"(같은 개념 유지)인데 T3에서 새 개념으로 이동.

### P4 — 마스터 도달이 비현실적이거나 영영 불가능할 수 있다 (★★☆)

마스터 = (모든 핵심 개념 각각 누적 score≥3) AND (통합 답변 score≥4).

개념 집합이 P1처럼 불릿 6개라면 6개를 각각 ≥3 받고 통합까지 ≥4를 받아야 한다. 그런데
missed_concepts 가 안 줄고(P2) 점수가 낮게 눌리고 노이즈가 크면(P3), 마스터는
사실상 도달 불가에 가깝거나 운에 좌우된다.

참고: README는 "Q12 토픽 답변 3회로 mastered 도달"이라고 적고 스크린샷도 그렇게 캡처돼 있다.
현재 프롬프트(6개 개념 × ≥3 + 통합 ≥4)로는 3회로 불가능하다. README/스크린샷은 프롬프트
고도화 커밋(1ae6589, 5/21) **이전** 상태다 — 문서가 현재 동작과 어긋나 있다.

### P5 — 토픽 콘텐츠 구조를 프롬프트가 전혀 활용하지 못한다 (★★☆)

`Q12.md` 는 구조가 명확하다: 정의 → 메커니즘(3불릿) → 예시(stateless/stateful 코드) →
주요 이점(5불릿) → 요약 → **`<deflist>` 접이식 Q&A 2개**(재사용성·테스트 / 회피 시나리오).

- 프롬프트는 .md 전체를 불투명한 덩어리로 받는다. 모델이 매번 구조를 재발견해야 한다.
- **`<deflist>` 의 Q&A 쌍은 사실상 검증된 질문 + 모범답안인데** 프롬프트가 이를
  "질문 은행 / 정답지"로 쓰라고 지시하지 않는다. 채점 앵커로 쓰면 P3이 크게 완화된다.
- `<deflist ...>` `<def title=...>` 같은 XML 태그가 그대로 프롬프트에 들어가 노이즈가 된다.
- 토픽의 헤드라인 질문("State hoisting의 이점은?")은 좁은데, 코치는 정의·메커니즘·회피
  시나리오까지 전체를 퀴즈한다 — 문서 의도와 코칭 범위의 불일치.

### P6 — 루브릭 상단(4~5점)이 원문 기준과 자기모순 (★☆☆)

채점은 "토픽 원문" 기준이고, 범위 가드레일(규칙 6)은 "원문에 없는 개념은 평가 금지"다.
그런데 5점 조건은 "전이(transfer)·트레이드오프 추론"을 요구한다. Writerside 문서는
면접 대비 요약이라 트레이드오프를 거의 다루지 않는다 → 학습자가 원문만 충실히 반영하면
5점은 구조적으로 못 받는다. 루브릭 최상단이 도달 불가이거나 가드레일과 충돌한다.

### P7 — 인플레이션 방지 규칙의 부작용 (★☆☆)

"새 정보 없으면 점수 안 오름" + 콜드 첫 시도 + 보강 루프가 겹치면, 적당한 첫 답(2점)을
한 학습자가 보강 답을 내도 표현만 바꾼 걸로 판정돼 점수가 동결될 수 있다. 인플레이션
방지는 있는데 "진짜 향상은 인정"하는 대칭 규칙·보정이 없다. 학습자가 2점에 갇힐 수 있다.

### P8 — 문서 드리프트 (☆☆☆ 사소)

README의 학습 사이클·마스터 설명·스크린샷이 현재 프롬프트와 불일치 (P4 참조).

## 권장 수정

### Tier 1 — 프롬프트만으로 즉시 (코드 변경 없음, 큰 효과)

1. **개념 분해 원칙을 명시.** "한 토픽의 핵심 개념은 3~5개. 문서 불릿 하나하나가 개념이
   아니다. 개념 = 구분되는 *메커니즘/아이디어* 단위이며, 같은 원인의 여러 *결과/예시*는
   하나로 묶는다." 라고 못 박는다.
2. **점수 ↔ missed_concepts 정합 규칙 추가.** "한 답변이 여러 추적 개념을 충분히 다뤘으면
   그 개념들을 *모두* missed_concepts 에서 제거한다." 를 명시. P2의 패널 미갱신 버그를 막는다.
3. **루브릭 앵커 + 예시 주입.** 시작 시 코치가 이 토픽에 한해 "3점이면 이런 답, 4점이면
   이런 답" 한 줄짜리 앵커를 잡게 하거나, 프롬프트에 짧은 worked example을 넣는다.
4. **`<deflist>` 를 정답지로 활용.** 토픽 콘텐츠를 넘길 때 deflist Q&A를 분리해
   "[검증된 질문·모범답안]" 섹션으로 코치에게 주고, 채점·역질문의 앵커로 쓰라고 지시.
   동시에 학습자에게 보이는 본문에서는 `<deflist>` XML 태그를 제거한다 (`topics.ts` 소폭 수정).
5. **루브릭 상단 정리.** 5점을 "원문 범위 안에서의 전이·연결"로 재정의하거나, 원문이 얕은
   토픽은 4점을 천장으로 인정. 가드레일과의 모순 제거.

### Tier 2 — 구조 개편 (제대로 된 해결)

두 관심사를 분리한다:

- **코칭 대화** — 파인만 루프. 그대로 유지.
- **개념 마스터 추적** — 명시적·영속적으로 만든다.

구체적으로:
1. 세션 시작 시 코치가 **고정 개념 체크리스트**(3~5개, 각 개념별 "완전한 답이 담아야 할
   한 줄")를 생성 → 세션에 영속화(`sessions` 컬럼 또는 `concepts` 테이블).
2. 매 턴 채점 JSON을 **개념별 점수 맵**으로 바꾼다. 턴당 단일 `score` 대신
   `concept_scores: { conceptId: 0~5 }`. 답변이 건드린 개념 각각에 점수를 준다.
3. 앱은 개념별 best score 를 저장. missed_concepts = best<3 인 개념. 패널이 실제 진척을 반영.
4. 마스터 = (모든 개념 best≥3) AND (통합≥4) — 이제 저장 데이터로 *실제 계산 가능*.
5. `ScorePanel` 이 개념별 진척을 표시하도록 갱신.

Tier 2는 JSON 스키마 + DB 스키마 + 채점 추출 + 패널을 건드리는 실제 리팩터링이지만,
P1~P4를 근본적으로 없애는 유일한 방향이다. Tier 1은 그 전까지의 가교다.
